# GridPass native feasibility probe

This is a source-only compatibility probe for a proposed offline transfer of
selected DBeaver table-layout settings. There is no product UI or completed
layout-transfer claim yet.

The hosted probe uses the official DBeaver Community Edition 26.2.2 GUI in a
disposable profile and workspace, with a pinned official Xerial SQLite JDBC
driver and three original local SQLite tables. It first records the actual
startup, connection and native UI structure. A successful bootstrap alone does
not establish layout fidelity. The full acceptance contract is in
[docs/native-contract.md](docs/native-contract.md).

The intended product will read only explicitly selected saved-data-filter.xml
files. It will transfer column position, visibility, pinning and sort priority
from one selected entry to an existing target entry with the exact same unique
flat column names. Target identity, bindings, predicates, opaque values and all
other entries remain the target's own. No SQL predicate copying, database
operations, connection handling, workspace scanning or automatic installation
is part of the product.

Native DBeaver reads Java-serialized values. The product must never invoke Java
deserialization: pinned values will be matched against a finite canonical
Integer0–255 whitelist generated by an official JDK. Other target values remain
opaque and unchanged. This does not certify an entire file as safe to load in
DBeaver. The native gate accepts only the original synthetic disposable fixture.

Users must close DBeaver before replacing a reviewed configuration copy: its
delayed settings save can overwrite external edits. Native behavior, the actual
canonical pin whitelist and byte-preserving output remain pending this probe.

downloaded into the hosted runner and are not included in this source package
